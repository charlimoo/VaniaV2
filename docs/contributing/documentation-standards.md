# Documentation Standards

Documentation should make future changes safer.

## Write For Developers

- Start with ownership: which files or modules own the behavior.
- Explain contracts: inputs, outputs, keys, state shape, headers, and side effects.
- Include validation steps.
- Link related pages.
- Call out role, billing, and canvas implications.

## Language

- Developer documentation should be in English.
- Product UI labels and examples may remain Persian when documenting visible app copy.

## When To Update Docs

Update docs when changing:

- Agent definitions
- Capability registration
- Tool or form contracts
- Canvas component keys or state shape
- Role and eligibility rules
- Billing restrictions
- API request/response shapes
- Local setup or deployment steps
